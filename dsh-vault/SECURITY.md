# Security 安全边界（dsh-vault）

## 它保护什么

`dsh-vault` 的目标：**本机加密保存账号密码**，只有在这台电脑、输入主密码的情况下能读取。

它做到：
- 主密码不落盘、不打印、不进 LLM、不经过对话记录。
- 条目名也加密，解锁前看不到任何条目。
- 解锁状态只保存在 dsh **进程内存**里，重启 dsh 自动重新锁定。
- 管理页 / 工具仅在 dsh 已绑定的回环地址上暴露。

## 它不防御什么（明确边界）

| 威胁 | 是否防御 | 说明 |
| --- | --- | --- |
| 别人拿到仓库代码 | ✅ | 仓库不含 `vault.json` / `machine.key` / 主密码。 |
| 别人拿到 `vault.json` 密文，但没有主密码、没有 `machine.key` | ⚠️ 基本安全 | 无 key 时离线破解极难（PBKDF2 60 万轮 + 256 位）。 |
| **同一台已登录电脑上的恶意程序** | ❌ **不防御** | 本机有 `machine.key`；你解锁后进程内存里是明文。本地有权限的程序/木马可读取。 |
| **主密码泄露到别处** | ❌ | 主密码是钥匙；一旦与密文（+ 本机 key）同时泄露即可解密。 |
| 密码**暴露在对话/聊天/明文文件** | ❌ | 工具只能保证「发送前安全」，不能收回你已经贴出去的内容。 |
| **物理拿到并登录这台电脑**、且你已解锁未锁 | ❌ | 内存里的明文可被读走。 |

## 你不会因为「上传到 GitHub」而被破解

- 仓库 `baomi` 只含代码与文档，**不含任何真实凭据**（`.gitignore` 已禁止 `vault.json` / `machine.key`）。
- 你本机的保险库数据在 `~/.dsh/vault/`，**不随仓库上传**。

## 你需要自己遵守的 3 条

1. **不要在主密码、账号密码放进 dsh 对话或明文文件**；添加条目用 `dsh-vault add` 或本机 `/vault` 页面。
2. **不要在解锁状态下放任本机被他人/恶意软件操作**；离开时点页面「锁定」或重启 dsh。
3. `machine.key` 是本机绑定密钥，**不要外传**；换电脑需连它一起迁移（但这会扩大泄露面，请谨慎）。

## 如需额外加密（高于本工具默认）

- 把 `~/.dsh/vault` 整个目录放进系统级的加密盘 / BitLocker / VeraCrypt。
- 操作系统账号用强密码 + 锁屏；避免共享这台 Windows 账号。
